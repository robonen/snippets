# brain · план системы

> **Статус: проектирование, ревизия 2.** «brain» — рабочее имя; в форматы
> данных оно не утекает (ленды именуются по модулям).
>
> Second brain на [sync-crdt](../../sync-crdt): local-first пространство
> модулей, куда переезжает [kcal](../../kcal) и где живут заметки, задачи и
> остальное. Обычный Vue 3.6, SFC `<script setup>` (**без Vapor** —
> `@robonen/primitives` и `@robonen/writekit` его пока не поддерживают) +
> экосистема `@robonen/*`. Доступ и шифрование — [01-security.md](01-security.md).
> Фон: `../../research-docs/` — реверсы синка Notion/Linear/Todoist и др.

---

## 1. Что это

Одно PWA (один origin, один service worker, одна установка), внутри —
**модули**: заметки, задачи, kcal, дальше по мере надобности. Всё работает
офлайн, синк — фоновая забота лендов, не пользователя. Телефон и десктоп
равноправны: захват чаще с телефона, разбор и письмо — с десктопа.

Чем **не** является: не платформа с runtime-плагинами, не переписывание
sync-crdt (brain — его второй потребитель, ядро живёт своей жизнью), не клон
Notion — только то, что нужно одному человеку.

## 2. Функционал

### Сквозное — то, что делает модули системой

- **Инбокс-захват.** Глобальная кнопка и хоткей: кинуть мысль, ссылку, текст —
  без выбора «куда». PWA **share target**: шаринг из любого приложения
  телефона падает в инбокс. Разбор инбокса — жест «в заметку / в задачу /
  в закладку».
- **Экран «Сегодня».** Стартовый дашборд: заметка дня, задачи на сегодня,
  сводка kcal. Модули отдают виджеты через контракт — экран собирается сам из
  включённых модулей.
- **Ссылки между сущностями.** `[[...]]` указывает на что угодно в любом
  модуле: заметку, задачу, продукт. Адрес уже есть — `Link` из `@sync/core`
  глобально уникален (ленд + id). Обратные ссылки показываются у цели.
- **Командная палитра + глобальный поиск.** Один вход: команды модулей,
  переходы, поиск по всем модулям (контрактный `search`).
- **Календарь-вид.** Всё пространство по датам: задачи, daily notes, вес,
  траты, привычки — модуль отдаёт события через контрактный `calendar`.
- **Ревью недели.** Направляемый ритуал: разбор инбокса до нуля, задачи без
  движения, resurfacing давно не открывавшихся заметок, итоги в daily note.
- **Напоминания.** Локальные PWA-уведомления: дедлайны, привычки, дни
  рождения. Без пуш-сервера — устройство напоминает само.
- **Граф связей.** Визуализация entity-ссылок между всеми модулями; строится
  на уже материализованном индексе wikilinks. Низкий приоритет — осознанно.
- **Бэкап и экспорт.** Всё пространство одним файлом; заметки дополнительно
  экспортируются в markdown (страховка от собственного формата).

### Заметки — ядро

- Блочный редактор **`@robonen/writekit`**: параграфы, заголовки, списки,
  todo-списки, цитаты, код, callout, картинки; марки bold/italic/…/link;
  slash-меню, bubble-меню, markdown-правила ввода, drag-перестановка, undo.
- Wikilinks `[[...]]` с автодополнением (кастомная марка writekit) и панель
  обратных ссылок.
- Теги; список заметок с сортировкой и фильтром; закреплённые.
- **Заметка дня** (daily note) — создаётся по требованию, точка входа журнала;
  чекбоксы в ней видны модулю задач (см. ниже).
- **Шаблоны**: заготовки daily note, ревью, карточек — через slash-меню и при
  создании.
- **История версий**: таймлайн изменений с восстановлением — op-лог CRDT уже
  хранит историю, нужен только UI поверх.
- **Вложения** (файлы/PDF сверх картинок) — отдельной стадией: тянут
  blob-стратегию ядра, большие бинари не должны жить в юнитах ленда.

### Задачи

- GTD-lite: инбокс → сегодня → запланировано → когда-нибудь; проекты как
  группировка; дедлайны; повторяющиеся задачи.
- Чекбокс в заметке можно «поднять» в задачу — она остаётся связана с местом
  в тексте через entity-ссылку.

### Закладки / read-later

URL из share target падает закладкой: статусы «прочитать/прочитано»,
теги, аннотация-заметка. Почти всё даёт инбокс — самый дешёвый модуль.

### Трекеры — отменены

Модуль был написан и удалён по решению 2026-08-24: привычка — это
повторяющаяся задача, которая уже есть в «Задачах», а вес живёт в kcal. На
самостоятельный модуль оставалось настроение и произвольные метрики — мало.
Код остаётся в истории git.

### Финансы

Ручной учёт трат: быстрый ввод из инбокса («250 кофе»), категории, месячная
сводка. Без банковских импортов.

### kcal

Как есть: дневник питания, каталог продуктов, штрихкоды, статистика, вес,
профиль. Плюс виджет на «Сегодня» и выдача в глобальный поиск.

### Вторая волна (когда-нибудь, по реальной жизни в системе)

- **Люди (personal CRM)**: карточки людей, дни рождения, «о чём говорили»,
  упоминание человека через `[[...]]` из любой заметки.
- **Медиа-лог**: книги/фильмы/игры — статусы, оценки, цитаты уезжают в
  заметки со ссылкой на источник.

Отвергнуто после обсуждения: рецепты, флэшкарты (SRS), публикация заметок
наружу.

## 3. Решения

### Р1 · Оболочка + модули-слои

**Ревизия 3: модули — слои `vite-layers`, а не только пакеты.**

Пакетов workspace оказалось мало. Все шесть модулей ехали в бандл всегда,
даже неиспользуемые, и цена набора росла монотонно. Слои дают две вещи,
которых у пакетов нет:

1. **`feature()` — компайл-тайм макрос.** Выключенный модуль не «перестаёт
   роутиться»: подставленный `false` делает ветку статически мёртвой, и её
   `import()` выпиливается вместе с чанком. Проверено: с `finance` — шесть
   модульных чанков, без него пять.
2. **Файл модуля перекрывается без форка.** Свой экран кладётся по тому же
   относительному пути слоем выше, базовый достаётся через `#super`.

Цена и следствия:

- Файлы слоя лежат под своим именем (`modules/notes/src/notes/…`). Без этого
  `@/db/models` был бы у пяти модулей одним путём, и резолвер брал бы первый
  попавшийся — оверрайды стали бы лотереей.
- Модули остаются и пакетами: `package.json` нужен для резолва зависимостей
  (`vue`, `@brain/ui`, `@sync/*`) и для своих гейтов. Слои и пакеты решают
  разные задачи и не конкурируют.
- `vite.config.ts` приложения импортирует **собранную** точку входа
  vite-layers: `exports` пакета ведёт на `src/index.ts`, а его внутренние
  импорты безрасширенные, и нативный ESM-загрузчик Node, которым Vite читает
  конфиг, такое не резолвит. Когда `exports` будет указывать на сборку, строка
  станет обычным `from 'vite-layers'`.

### Р1a · Регистрация статическая

Оболочка (`apps/web`) владеет сборкой пространств, роутером, инбоксом,
«Сегодня», палитрой, бэкапом, PWA. Модуль — pnpm-пакет с декларацией:

```ts
// packages/module-kit — единственная точка связи оболочки и модулей
interface BrainModule {
  id: string;                 // 'kcal' — префикс маршрутов и имён моделей
  title: string;
  icon: Component;
  land: {
    id: Link;                 // фиксированный, как LAND_ID у kcal
    root: ModelName;
    seed?(space: Space): void;
  };
  routes: ModuleRoute[];      // лениво загружаемые экраны
  widgets?: Widget[];         // карточки для «Сегодня»
  commands?: Command[];       // палитра и разбор инбокса
  search?(space: Space, query: string): SearchHit[];
  resolveRef?(link: Link): RefPreview | null; // как показать [[ссылку]] на свою сущность
  calendar?(space: Space, range: DateRange): CalendarEvent[]; // календарь-вид
  reminders?(space: Space): Reminder[];       // локальные уведомления
  review?: ReviewStep[];      // шаги модуля в ревью недели
}
```

Регистрация статическая — импорт в конфиг оболочки; runtime-плагины
отвергнуты (сложность без пользы для одного пользователя).

### Р2 · Ленд на модуль + мета-ленд оболочки

Ленд — единица синка, прав и (после S6) шифрования, поэтому граница лендов =
граница модулей: `meta` (настройки, инбокс, включённость модулей), `kcal`
(**тот же ленд-id, что сейчас** — данные переезжают без конвертации),
`notes`, `tasks`… Выборочный синк, выключение модуля = закрытие vault'а.
Кросс-модульные ссылки лендам не мешают: `Link` адресует через границы.

Цена: N vault'ов и каналов — N единицы, бюджет старта в гейте Э1.
Отвергнуто: один ленд на всё — столкновения имён, права «всё или ничего»,
переливка kcal.

### Р3 · Имена моделей с префиксом модуля

Реестр `Models` глобальный на приложение. `model('notes/note', …)`; хелпер
module-kit префиксует и закрепляет конвенцию типом, а не ревью.

### Р4 · Обычный Vue, SFC `<script setup>`

`@robonen/primitives` и `@robonen/writekit` требуют обычный Vue (`^3.5`),
vue-router без Vapor тоже штатный. Компоненты пишутся как SFC
`<script setup lang="ts">` — как в доках экосистемы; типы проверяет `vue-tsc`.

Что это меняет в коде экранов kcal при переезде (§5): функция-компонент Vapor
становится SFC — в Vapor тело функции и есть setup, а в vdom оно зовётся на
каждый рендер, и `computed` внутри пересоздавался бы вместе с подпиской. Плюс
ключи в списках. Модели и логика от рендерера не зависят вовсе, поэтому весь
слой данных переехал без правок.

Приятное следствие ухода с Vapor: иконки lucide снова рендерятся обычными
vnode'ами — сериализация иконки в строку и `v-html` (обход для Vapor) отменены.

### Р5a · Стартовая страница и хук `capture`

Домашняя страница браузера — отдельный маршрут `/`, построенный вокруг одного
действия: поле захвата в фокусе с первой миллисекунды. Открыл вкладку,
написал, Enter — и никуда идти не пришлось.

«Сразу в задачу или трату по синтаксису» потребовало нового хука контракта —
`capture(ctx, text)`. Оболочка НЕ должна знать, что «250 кофе» это трата, а
«купить молока !высокий» — задача: разбор живёт там же, где домен, а старт
лишь спрашивает у каждого модуля «твоё?» и показывает ответивших. Иначе поле
ввода учило бы синтаксис каждого модуля, и добавление модуля правило бы
оболочку.

### Р5 · UI-кит на `@robonen/primitives`, оформление своё

`packages/ui`: обёртки над примитивами (`Sheet`, `Modal`, `TextField`,
`SwitchField`, `Meter`, `Button`, `Card`, `EmptyState`, `PageHeader`) + токены
Tailwind 4 + иконки lucide-data. Поведение — ловушка фокуса, `inert`, ARIA,
клавиатура — целиком на примитивах; наше только оформление и геометрия.

**Оформление — графит** (ревизия 4; индиго-на-графите ревизии 3 отвергнуто:
хрома 0.012–0.016 на поверхностях читалась как видимый фиолетовый, и экран
выглядел очередной админкой). Ориентиры названы прямо: Linear, Vercel,
[cobalt](https://github.com/imputnet/cobalt). Три их общих приёма:

1. **Нейтрали истинно серые**, без подтона. Любая хрома на поверхности — и
   графит перестаёт быть графитом.
2. **Границы полупрозрачные**, а не сплошные: `rgb(255 255 255 / 8%)` темнеет
   ровно настолько, насколько темнее подложка, поэтому одна переменная годится
   и карточке, и всплывающему слою, и подсветке.
3. **Главное действие — инверсия нейтрали**, а не цветная заливка: белая
   кнопка на тёмном, тёмная на светлом. Цвет остаётся смыслу — ссылке, фокусу,
   состоянию, — а не «здесь кнопка».

Свет по времени суток сохранён, но обесцвечен (хрома 0.03 вместо 0.14): это
должен быть свет, падающий на серое, а не подсветка.

Цвета по-прежнему в OKLCH там, где нужен ряд. Цветовое пространство выбрано не по моде: в
sRGB два цвета с одинаковыми числами воспринимаются разной светлоты, и
семантический ряд неизбежно пестрит. В OKLCH первое число — воспринимаемая
светлота, поэтому «успех / риск / ошибка» держатся на одной `L`, а тёмная
тема получается сдвигом светлоты, а не подбором на глаз.

Вместе с палитрой заведены токены ДВИЖЕНИЯ: свои кривые вместо вялых
встроенных, `ease-in` в интерфейсе запрещён (он тянет тот самый первый
момент, на который смотрят внимательнее всего), длительности до 300 мс,
утилиты `pressable`, `hoverable`, `glass`, `stagger`.

**Формы для десктопа и телефона разные, а не одна растянутая.** На широком
экране постоянная боковая панель, на телефоне — стеклянная нижняя навигация и
плавающая кнопка захвата. Переключение по вьюпорту: выбор «панель сбоку или
вкладки снизу» зависит от устройства. Контейнерные запросы применяются к
карточкам, которые обязаны одинаково работать и в узкой колонке, и во весь
экран, — там это правда, а в каркасе было бы притворством.

Устройство важнее палитры: тема меняет значения семантических переменных
(`surface`, `text-soft`, `line`), а не набор утилит. `bg-surface` пишется один
раз и работает в обеих темах — альтернатива с `dark:`-вариантом на каждом
классе означала бы, что каждый компонент помнит про обе темы, и один забытый
вариант ломает контраст. Имена — по роли, а не по цвету: роль переживает смену
палитры, «серый-200» — нет.

### Р6 · Редактор — writekit, тексты живут в его CRDT, ленд возит байты

У writekit собственный CRDT (`@robonen/crdt`: RGA-текст, fractional-индексы
блоков, Peritext-марки) за плагабельным `CrdtProvider`, синк — op-батчи
байтами через любой транспорт. Готовая rich-text-семантика слияния лучше
самодельной поверх `text()`, поэтому:

- тело заметки = документ writekit; его op-батчи и снапшоты лежат **байтами в
  юнитах ленда** (`ops: list(bytes)` + периодический снапшот с компакцией);
- транспорт, персист, кросс-таб и сервер — прежняя работа `@sync`, ему всё
  равно, что в байтах;
- метаданные заметки (заголовок, теги, ссылки, даты) — обычные атомы `@sync`,
  по ним работают списки, поиск и backlinks без разбора тела;
- индекс wikilinks материализуется при записи: провайдер отдаёт документ,
  модуль вынимает ссылки в `index`.

Альтернатива — свой `CrdtProvider` поверх `text()` `@sync` — остаётся
запасной унификацией, если два CRDT в одном приложении начнут мешать.
Спайк-неделя в начале Э3 отвечает на главные вопросы: рост op-лога,
компакция, стоимость холодного открытия заметки.

### Р7 · Один nitro-сервер, мультиленд

Серверная часть kcal (WS-бинарь + POST-фолбэк) обобщается: одно WS-соединение
мультиплексирует ленды — адрес ленда в каждом кадре, а не в URL. Авторизация —
прежний токен на всё пространство; настоящие права придут из S6 ядра
ортогонально.

**Уточнение по факту Э2 (сделано):** сервер — не пир CRDT, как был у kcal, а
**слепой append-only журнал запечатанных кусков**. Из-за E2E иначе нельзя:
ленды запечатаны на устройстве, ключа у сервера нет, и `exchange()` ему гонять
не по чему — слияние осталось на клиентах, сходимость держится на
идемпотентности применения. И никакого Redis: сервер свой, инстанс один,
хранилище — файлы. Протокол, инварианты и запуск — [04-server.md](04-server.md).

## 4. Структура репозитория

Новый корень `snippets/brain/`, pnpm-workspace:

```
brain/
  apps/web/            # оболочка: роутер, инбокс, «Сегодня», палитра, PWA, бэкап
  apps/server/         # nitro: мультиленд-синк, слепой журнал шифртекста (04-server.md)
  packages/
    module-kit/        # контракт BrainModule, хелперы лендов/моделей/ссылок
    ui/                # обёртки primitives + токены + иконки
    auth/              # конверт DEK/KEK, passkey, фраза восстановления, замок
    std/               # хелперы без домена и без UI: даты, числа
  modules/               # каждый — И слой vite-layers, И пакет workspace
    notes/  tasks/  kcal/  bookmarks/  finance/
      app.config.ts      # defineLayerConfig({ name })
      package.json       # зависимости и гейты
      src/<id>/…         # под своим именем — иначе пути слоёв столкнутся
```

Как написать модуль — [02-module-guide.md](02-module-guide.md): контракт,
каналы, хуки, гейты. Как его нарисовать — [03-design.md](03-design.md):
язык оформления и чек-лист экрана.

Слои — DAG без циклов:
`apps/web → modules/* → module-kit → ui → std → @robonen/{primitives,writekit,stdlib}`.
Модули друг про друга не знают; связи между ними — только entity-ссылки и
контракт. Внутри модуля декомпозиция kcal: `screens → features → db →
entities`; своего `shared` у модуля нет — такое уезжает в `packages/`.

`std` появился при переезде kcal: `dates` и `numbers` понадобятся не одному
модулю, а в `ui` они не помещаются (не про интерфейс) и в `module-kit` тоже
(не про контракт). Планка входа высокая — всё, что уже есть в
`@robonen/stdlib`, туда не дублируется; `format` дневника (ккал, граммы)
остался в модуле, потому что это домен.

Стек: Vue 3.6 (vdom, TSX), Vite 8 (rolldown), Tailwind 4, vitest,
`@robonen/eslint`, `@robonen/tsconfig`, date-fns, lucide-data.

## 5. Переезд kcal

1. **Логика переезжает как есть**: `entities/`, `db/models`, `db/sync`,
   расчёты и тесты не зависят от рендерера. ✅ сделано — правки свелись к путям
   импортов и префиксу имён моделей (`kcal/food`).
2. **Экраны переписываются** с Vapor-функций на `defineComponent` + `packages/ui`:
   семь экранов, дизайн и вёрстка переносятся, поведение шитов даёт
   primitives. Это цена Р4, заложена в оценку Э1.
3. **Данные не конвертируются**: ленд-id и формат прежние. Пути: бэкап v1,
   синк через сервер, плюс одноразовая переливка — оболочка видит старую базу
   `kcal-sync` в IndexedDB, открывает старый vault, сливает паки, помечает
   перенос выполненным.
4. Старое приложение живёт на своём URL до конца Э2, потом редирект.

**Гейт производительности Э0 переписан, и это честнее исходного.** Было

Замер: свой код 3.4 KB gz, Vue 31.2, ядро `@sync` 35.3, стили 3.9 — итого
73.8 KB gz. Бюджет, на 96% состоящий из фундамента, не способен поймать то,
ради чего заводился: разрастание кода оболочки. Поэтому он разделён — свой код
(≤ 8 KB gz) и первая загрузка целиком (≤ 80 KB gz). С модулем kcal:
18.0 + 4.9 + 31.2 + 35.7 = 89.8 KB gz.

## 7. Риски

| Риск | Митигция |
|---|---|
| Два CRDT в одном приложении (writekit + @sync) | Р6: границы жёсткие — writekit владеет телом заметки, @sync всем остальным и транспортом; спайк в начале Э3; запасной путь — свой `CrdtProvider` поверх `text()` |

| sync-crdt — R&D с правом на переписывание | модули касаются только публичного API `@sync/core` и module-kit; новый API ядра = правка module-kit, не N модулей |
| Экосистема `@robonen/*` v0 (primitives 0.0.6, writekit 0.0.4) | автор — тот же человек: недостающее чинится в экосистеме, а не обходится в brain; версии пинятся точно |
