## ADR-001 · Отдельное ядро; vue-sync-engine переписывается 🟢

**Контекст.** vue-sync-engine — server-authoritative кэш: истина на сервере,
`fetch` в `QueryGraph`, локальные правки живут как оптимистичные патчи с откатом.
baza — local-first CRDT: истина локальна, сервер — лишь релей байтов.

**Решение.** Пишем `@sync/*` как независимый монорепо-проект. vue-sync-engine
**перерабатывается** поверх ядра: `Mirror`, `patches`, `mutationQueue` и
патч-протокол удаляются, а не оборачиваются адаптерами. Обратная совместимость
не является целью ([правило 1](../PRINCIPLES.md#правило-1--это-rd-совместимость-не-ограничение)).

**Последствия.**
- ✅ Ядро тестируется без Vue, работает в Node/воркере/Deno.
- ✅ Нет двойной поддержки, нет адаптеров, нет legacy-веток в коде.
- ✅ Из vue-sync-engine остаётся то, что реально ценно: слой определения
  запросов, дедуп подписок, Vite-плагин, DevTools.
- ❌ Публикуется как новый major с явным breaking-change; старый playground
  переписывается вместе с библиотекой.

**Альтернативы.** Пятиэтапная миграция `M0→M5` с сохранением обоих путей —
отвергнута: внешних пользователей нет, а поддержка совместимости с самим собой
удваивает работу и консервирует ровно те абстракции, от которых мы уходим.

## ADR-002 · Переносим файберную модель 🟢

**Контекст.** В первом наброске плана предполагалось отказаться от файберов и
развести «синхронное чтение из памяти» и «асинхронную гидрацию». Разбор
`$mol_wire` ([01](01-mol-wire-internals.md)) показал, что файберы — это ~350
строк обычного JS без компиляторной магии.

**Решение.** Переносим полностью: Suspense через `throw Promise`, одноразовые
`Task` с позиционным переиспользованием, `sync()`/`async()`/`probe()`/`race()`.

**Последствия.**
- ✅ `pawn.title()` остаётся синхронным, хотя под ним IDB + AES + проверка подписи.
  Без этого весь API моделей становится async и заражает вызывающий код.
- ✅ Код baza портируется почти транслитерацией, а не переписыванием.
- ✅ Автоматический GC по достижимости: ленд жив, пока на него кто-то смотрит.
- ❌ Порог входа: любой код в файбере обязан быть перезапускаемым.
- ❌ Отладка требует спец-инструментов (подмена `stack`, id у файберов).

**Альтернативы.**
- «Всё async» — отвергнуто: `await` в каждом геттере модели, невозможно отдать
  геттер в шаблон Vue.
- Явная фаза гидрации + `resource()` — отвергнуто: не решает случай, когда
  подгружать надо *в середине* вычисления (расшифровка блоба по ссылке из
  другого ленда — [land.ts:1361](../../baza/land/land.ts#L1361)).

## ADR-003 · Субстрат — `alien-signals/system`, а не `alien-signals` 🟢 {#adr-003}

**Контекст.** Нужен граф зависимостей с двухцветной инвалидацией. Кандидаты:
свой с нуля (как в mol), `alien-signals` целиком, `@vue/reactivity`.

**Решение.** Берём **низкоуровневый** `createReactiveSystem` из
`alien-signals/system` и пишем поверх свой тип узла `Fiber`. Высокоуровневые
`signal()` / `computed()` / `effect()` **не используем**.

**Обоснование — конкретное.** `computed()` из `alien-signals@3.2.1` некорректен
для нашей модели, если геттер бросает. В `updateComputed`:

```js
c.flags = 1 | 4                                     // Mutable | RecursedCheck
try   { return old !== (c.value = c.getter(old)) }
finally {
  c.flags &= ~4                                     // → flags = 1, НЕ Dirty
  purgeDeps(c)                                      // ← режет незапрошенный хвост
}
```

1. При `throw` значение не присваивается, а флаги остаются «чистыми». Следующее
   чтение (`flags & Dirty` = 0, `flags & Pending` = 0, `!flags` = false) **вернёт
   протухшее значение молча**, не перезапустив геттер. Для Suspense это фатально.
2. `purgeDeps` в `finally` обрезает зависимости, не собранные до точки броска, —
   ровно противоположно тому, что нужно ([01 §4](01-mol-wire-internals.md#почему-track_cut-не-вызывается-при-промисе)).

Своё `update()` через `createReactiveSystem` снимает оба вопроса, при этом мы
получаем готовые, отбенчмаченные `link/unlink/propagate/checkDirty/shallowPropagate`.

**Последствия.**
- ✅ Не пишем сами самую тонкую часть (glitch-free распространение).
- ✅ Ядро зависит от одного пакета ~1 КБ.
- ⚠️ Зависим от `/system` — формально публичного, но низкоуровневого экспорта.
  Пин версии + свой набор тестов на поведение графа.

**Критерий пересмотра.** Зависимость выбрана под модель, а не модель под
зависимость ([правило 1](../PRINCIPLES.md#правило-1--это-rd-совместимость-не-ограничение)).
Если эксперимент C2 покажет, что `createReactiveSystem` не даёт нужной семантики
под Suspense, — **пишем свой граф**, а не выкручиваемся обходными путями. Это
равноправный вариант, а не аварийный: ~500 строк, идея взаимных индексов из
`$mol_wire_pub` описана в [01 §2](01-mol-wire-internals.md), тестовый набор
переиспользуется целиком.

**Альтернативы.**
- `@vue/reactivity` — не нужен мост в Vue, но ядро тащит Vue в воркер и в Node и
  теряет переносимость в React/Svelte. Отвергнуто.
- Свой граф — см. критерий пересмотра выше.

### Результат эксперимента C2 (2026-08-15) — субстрат подтверждён

Спайк `@sync/fiber` реализован и проверен: `pnpm typecheck` чист, `pnpm vitest run`
даёт **15/15**, `pnpm build` собирается. Обе гипотезы подтвердились.

**E1 — рёбра переиспользуются при приостановке.** Файбер, приостановленный после
двух зависимостей, при следующем прогоне получает **те же самые объекты `Link`**
(проверка через `toBe`). Контрольный тест показывает обратное: если на позиции
оказалась другая зависимость, ребро пересоздаётся — значит утверждение не тривиально.
Механизм — ветка переиспользования в `link()`, эквивалентная курсору `$mol_wire`.

**E2 — задачи идемпотентны.** Воспроизведён `Idempotence control` из
`mol/wire/fiber/fiber.test.ts`: через три прогона счётчик под `act()` равен **1**,
без обёртки — **3**.

**Что пришлось сделать иначе, чем в alien-signals.** Подписка выполняется **до**
пересчёта, а не после (`computedOper` линкует в конце). Иначе одноразовая задача,
досчитавшаяся синхронно, в момент `put()` видит `subs === undefined`, считает себя
никому не нужной и уничтожает себя — связь с родителем создалась бы строкой ниже,
уже на трупе. `$mol_wire_fiber.sync()` зовёт `promote()` перед `fresh()` ровно
поэтому; это выяснилось падением теста E2, а не чтением кода.

**Найденное свойство модели, которого не было в плане.** `complete()` уничтожает
одноразовые задачи, когда подграф досчитан. Значит при следующей инвалидации атома
`sync()` внутри него выполняется заново: **`sync()` — не кэш**. Кэширование
асинхронного источника — работа отдельного атома. Зафиксировано тестом
`sync() внутри атома — не кэш` и описано в [02 §4.2](02-runtime-design.md).

**Статус: 🟢 подтверждено.** Свой граф не нужен. Ни один из выявленных дефектов не
следует из устройства `alien-signals/system` — все три относились к нашему коду
(порядок подписки, дедупликация обёрток промиса, типизация) или к поставке типов
(расхождение №11).

Не проверено и остаётся в S1: перф-гейт (mitata, heap-delta, `--trace-deopt`),
вложенные приостановки в глубину, поведение `unwatched` во время ожидания,
утечки задач при уничтожении родителя.

## ADR-004 · Без декораторов 🟢

**Контекст.** В mol каналы объявляются через `@ $mol_mem`. В
[vue-sync-engine/lib/tsconfig.json](../../vue-sync-engine/lib/tsconfig.json)
включён `erasableSyntaxOnly` — декораторы (как и `enum`, и `namespace`) запрещены.

**Решение.** Каналы объявляются вызовом функции после класса:

```ts
class Land { total(next?: number) { /* ... */ } }
mem(Land.prototype, 'total')       // solo-канал
memKey(Land.prototype, 'passRank') // plex-канал по первому аргументу
```

Это ровно та же функция, что и декоратор, но вызванная руками — так же, как
`$mol_wire_solo(host, field, descr?)` умеет и то и другое.

**Последствия.**
- ✅ Работает `node --experimental-strip-types`, esbuild, rolldown без настроек.
- ✅ Имена функций сохраняются → пригодны как id файберов в отладке.
- ❌ Объявление канала и его реализация разнесены; нужен lint-контроль
  (правило: каждый метод, читающий `this.$`, должен быть в списке `mem`).

## ADR-005 · Один бинарный формат для провода, диска и дампа 🟢

**Решение.** `Pack` — единственный формат сериализации. Сообщение в сокете =
файл на диске = скачанный дамп = содержимое `.baza`-файла в репозитории.

**Последствия.**
- ✅ Один парсер, один сериализатор, ноль конвертеров.
- ✅ «Экспорт/импорт» и «бэкап» получаются бесплатно.
- ✅ Файл хранилища можно `mmap`-подобно использовать как арену аллокатора
  ([06](06-storage.md)).
- ❌ Формат становится публичным контрактом с первого релиза → нужны
  golden-vectors и версионирование ([03](03-binary-format.md)).

## ADR-006 · Между вкладками ходят сырые паки 🟢

**Контекст.** Сейчас вкладка держит `Mirror`, воркер — истину, между ними
`EntityPatch`/`QueryPatch`.

**Решение.** Каждая вкладка держит **полный** `Land`. По `BroadcastChannel`
летят `Pack`-байты. Юниты идемпотентны и коммутативны → вкладки сходятся сами.

**Последствия.**
- ✅ Минус `applyPatch`/`invertEntityPatch`/`Msg.EntityPatch`/`Msg.QueryPatch` —
  примерно 400 строк и целый класс багов рассинхрона.
- ✅ Вкладка работает и без воркера (деградация без кросс-таба).
- ❌ Память: полный набор юнитов в каждой вкладке. Смягчается тем, что юниты —
  общие `ArrayBuffer`, а не JS-объекты, и тем, что ленд — единица подгрузки.

**Роль SharedWorker сужается** до: один WebSocket на origin и один писатель в IDB.

## ADR-007 · `peer` = 8 байт, `land` = 16 байт 🟡

**Контекст.** В baza `peer` = 6 байт, `lord` = 12. При 10⁵ активных пиров
вероятность коллизии 6-байтового идентификатора становится неприятной
(~0.02 % по парадоксу дней рождения при 10⁵, и растёт квадратично).

**Решение.** `peer` = 8 байт (первые 8 байт хэша публичного ключа),
`land` = `peer(8) + area(8)` = 16 байт, `head` = 6 байт (локален внутри ленда,
там коллизии контролируются генератором).

**Последствия.** Юнит вырастает на 4 байта (~8 %). Приемлемо.
🟡 — пересмотреть, если бенчмарки покажут, что размер юнита критичен.

## ADR-008 · Свой детерминированный кодек значений 🟢

**Контекст.** Хэш юнита считается по байтам. Если один и тот же документ
кодируется по-разному в разных рантаймах — сеть тихо разваливается.

**Решение.** Свой CBOR-подобный кодек с жёсткими правилами каноничности:
сортированные ключи, минимальная длина varint, единственное представление для
`-0`/`NaN`, запрет на «дырявые» массивы. JSON и `structuredClone` не годятся.

**Последствия.** Обязательны golden-vectors в репозитории и fuzz round-trip.

## ADR-009 · Proof-of-Work выключен по умолчанию 🟢

**Контекст.** В baza «скорость записи» — часть ранга: `rate = late` требует ~15
нулевых бит в подписи, то есть десятки тысяч попыток.

**Решение.** Механизм переносим целиком, но дефолт — `rate = just` (0 бит).
PoW включается явно и только для публично-записываемых лендов. Считается в
отдельном воркере с отменой.

**Обоснование.** На мобильном 15 бит — это секунды CPU и разряд батареи на
каждую запись. Антиспам нужен единицам сценариев, а платить будут все.

## ADR-010 · Явный DI вместо ambient-контекста 🟢

**Контекст.** В mol/baza всё лежит в `$`, что даёт супер-способность: поднять
несколько независимых узлов в одном процессе и гонять между ними merge
([bench.ts](../../baza/bench/bench.ts)).

**Решение.** Ту же способность даём явным контейнером:

```ts
const node = createNode({ store, clock, identity, transport, log })
```

Никаких глобалов, кроме `activeSub` внутри рантайма (это дисциплина стека
вызовов, экземплярам не мешает).

**Последствия.** Мультипировые тесты остаются, но без магии — см. [10](10-testing.md).

## ADR-011 · Гранулярная реактивность коллекций 🟢

**Контекст.** `$mol_wire_dict` держит один `pub` на всю карту: изменение одного
ключа будит всех читателей. В [mirror.ts](../../vue-sync-engine/lib/src/tab/mirror.ts)
эта проблема уже решена вручную картой `versions`.

**Решение.** `ReactiveMap` с сигналом на ключ + отдельным сигналом на «форму»
карты (набор ключей). Читатель одного ключа не просыпается от изменения соседа.
Версии ключей создаются лениво и удаляются вместе с ключом.

## ADR-012 · Явная форма `sync()`; Proxy — вторична 🟢

**Контекст.** `$mol_wire_sync(obj)` — Proxy, оборачивающий каждый вызов.
Красиво, но: плохо типизируется, ломает tree-shaking, скрывает точку ожидания —
самое важное место для понимания кода становится невидимым.

**Решение.** Основная форма — явная: `sync(fn, ...args)`. Proxy-форма остаётся
как `syncAll(obj)`, помечается «для быстрого портирования» и не используется в
собственном коде ядра.

**Обоснование.** [Правило 3](../PRINCIPLES.md#правило-3--качество-кода-и-уместные-абстракции):
точка приостановки — это граница, которая обязана быть видна в месте вызова.
Прятать её за Proxy ради краткости — обмен читаемости на символы.

## ADR-018 · vue-sync-engine не переписывается и не воссоздаётся: его предметная область исчезла 🟢

**Контекст.** ADR-001 предполагал переработать vue-sync-engine поверх нового
ядра, сохранив «слой определения запросов, дедуп подписок, Vite-плагин,
DevTools». Владелец проекта поставил вопрос иначе: не переписывать, а сделать с
нуля в этом репозитории — либо признать, что для Vue-приложения отдельный движок
не нужен вовсе.

**Решение.** Второе. vue-sync-engine решал задачи **серверного кэша**: описать
запрос, привезти данные, положить в нормализованный кэш, наложить оптимистичный
патч, откатить при отказе (`Mirror`, `patches`, `mutationQueue`, `QueryGraph`).
В local-first архитектуре этой предметной области нет:

| задача движка | куда делась |
|---|---|
| определение запросов и `fetch` | данных «где-то там» нет — они в ленде; «запрос» = реактивное чтение модели или индекса |
| нормализованный кэш | сам ленд: юниты и есть нормальная форма, `Doc` — вид над ними |
| дедуп подписок | в ядре от рождения: `computed.keyed` на (модель × поле × ленд) |
| оптимистичные патчи и откат | записи сразу локальные и настоящие; сеть — фоновая досылка, откатывать нечего |
| очередь мутаций | журнал ленда + `vault` с накоплением непринятого |
| кэш между вкладками | `wire-bc`: вкладки — полноправные реплики |

Что Vue-приложению **действительно** нужно — тонкий мост, и он уже спроектирован
в [05 §1.8](05-model-api.md): `provideSpace`/`useSpace`, `useDoc`, `useValue`/
`useSync`, `useModel`. Это `@sync/vue` в этом же репозитории — не движок, а
переходник двух графов реактивности, односторонний (Vue читает нас, запись —
обычный вызов канала в обработчике).

**Последствия.**
- ✅ Стадия S8 сужается: достроить `@sync/vue` по 05 §1.8 плюс playground;
  строка «переписывание vue-sync-engine» из плана исчезает.
- ✅ Пропадает целый класс работы и кода, который пришлось бы поддерживать.
- ⚠️ Из старого движка не переносится ничего, включая Vite-плагин; DevTools —
  отдельная стадия S9 на инспекторе файберов.
- ❌ Существующий playground старого движка не мигрирует — новый пишется на
  мосту (и он же — приёмочный стенд S8).

**Отменяет** часть ADR-001: «vue-sync-engine перерабатывается поверх ядра» → не
перерабатывается; из него не берётся и «слой определения запросов» — в
local-first он не имеет предмета.

## ADR-017 · Сеанс чеканки: вкладки одного пира разводятся началом кольца счётчика 🟢

**Контекст.** ADR-006 велит каждой вкладке держать полный ленд, ADR-007 делает
пира хэшем публичного ключа — то есть у вкладок пир ОДИН. Счётчик `self` и метка
`(time, tick)` живут в памяти ленда, поэтому две одновременно открытые вкладки
чеканили один и тот же `self`: юниты складывались в один слот `(head, peer, self)`,
арбитраж выбирал один — и правка второй вкладки исчезала молча. Красный тест
стоял с S4.

**Решение.** У ленда появляется **сеанс** — 24-битное начало кольца счётчика
(`LandOptions.session`). Чеканка идёт по кольцу от начала сеанса с **пропуском
занятых** id; отмотка счётчика при гидрации остаётся только в детерминированном
режиме (сеанс 0) — при сеансах она вредна: обе вкладки отмотались бы к одному
максимуму и чеканили бы синхронно дальше.

Энтропию даёт **обвязка, а не ленд**: `randomSession()` живёт в `wire/tabs`, а
ленд по умолчанию детерминирован — по той же причине, по которой часы
инжектятся снаружи. Режим по умолчанию — однописательный, и это записано красным
тестом: «две вкладки БЕЗ сеансов правку теряют».

**Вероятности, чтобы решение не выглядело магией.** Столкновение требует
пересечения территорий двух случайных начал в кольце 2²⁴. Для двух вкладок по
`n` юнитов это ≈ `2n/2²⁴` за сессию (при `n = 100 000` — около 1.2 %), и
пересечение лечится пропуском занятых: чеканки перескакивают чужие
персистентные id, теряется только плотность нумерации. Молчаливая потеря
требует одновременной чеканки ОДНОГО id в окне доставки канала (≤ 5 мс) — при
случайных началах это исчезающе редко.

**Цена, вскрытая реализацией.** Векторные часы протокола (`Face`) индексируются
пиром, а сеансы расщепляют пира на несколько одновременных писателей: две
офлайн-вкладки пишут юниты с одинаковой меткой `(time, tick)` при разных `self`,
и дельта по строгому водяному знаку слепа в обе стороны — знак и счётчик у
обеих совпадают. Поэтому знак с сеансами достоверен только **строго ниже** своей
секунды, и `diffOf` пересылает пограничную секунду целиком, а `Fail Summ`
считает «мог видеть» включительно с ней. Повторная доставка идемпотентна,
секунда коротка; плата измерима и уплачена осознанно.

**Отвергнутые альтернативы.** Свой ключ на вкладку — ломает ADR-007 и подпись
S6; сессия в формате юнита — расширяет `self` сверх шести байт и ломает формат;
случайность внутри ленда по умолчанию — ломает воспроизводимость следа, на
которой стоит кросс-движковый гейт.

## ADR-016 · Источник истины в ленде — байты. Форма вида и раскладка индексов решаются отдельно 🟢

**Контекст.** Слою моделей (S4) нужен `Land`, и `Sand` (обычный объект, поля-свойства,
идентификаторы строками) со `SandUnit` (вид над байтами, поля-методы, `Link`)
структурно несовместимы. Вопрос решался замером: три рабочих прототипа с единым
интерфейсом и семью общими сценариями, независимый перезамер и двое проверяющих.

**Замер опроверг постановку вопроса.** Оба проверяющих независимо вынесли
«несопоставимо» и сошлись на трёх поправках:

1. **Бинарный прототип мерился без обязательного уровня индекса `head → peer → self`**
   ([04 §1](04-crdt-core.md)) — он не хранил проигравшие по LWW версии (`size()`
   10 000 против 11 000 на одном входе). С этим уровнем его 119 Б становятся 166,
   приём пачки 2.06 → 4.69 мс, и три победы из четырёх исчезают. Он сэкономил на
   работе S7, а сравнивался в сценариях S4.
2. **Отрыв на `order` в 8.6 раза — свойство алгоритма, а не представления.**
   Группировка на двух `Int32Array` вместо `Map<lead, Sand[]>` плюс плотная
   нумерация узлов переносимы и на объекты; около 28 % времени наивной версии —
   повторная свёртка LWW, которую она уже делала. На веере вместо цепочки отрыв
   падает до 2.3×.
3. **Самая цитируемая цифра — самая нерелевантная.** `memory/per-unit` снята на
   ленде, который никто не читал, а такого состояния у ленда не бывает. В рабочем
   состоянии — прочитан и подписан — расклад **850 / 969 / 841 Б**: разрыв между
   представлениями (163 Б) **втрое меньше цены подписки** (+613…+803 Б) и меняет
   знак. Выбирать представление по «119 против 282» значит оптимизировать пятую
   часть бюджета, четыре пятых которого лежат в числе подписок.

**Решение — по функциональности, а не по скорости.**

**Источник истины — байты.** Обычные объекты выбывают не по замеру (в приёме они
ровные), а потому, что `Sand` **не выражает формат провода**: конверсия теряет
`tag` (те самые два бита `term/solo/vals/keys`, по которым S4 отличает атом от
списка и словаря), `big`/`sizeBig`/`shot` и `kind`, а на большом санде приём
падает. Это не оптимизация, а недостающая функциональность: [ADR-005](#) обещает
один формат на провод, диск и память, а [06](06-storage.md) кладёт этот же файл
ареной аллокатора, и подпись в S6 считается **по байтам**. Ленд на объектах
теряет и предмет подписи, и предмет пересылки.

**Форма вида и раскладка индексов — отдельные решения, и они не про байты.** Два
байтовых прототипа различались не хранением, а тем, чем поля торчат наружу
(методы против геттеров) и как уложены индексы. Лучшие части берутся по
измеренным числам, а не пакетом:

| берём | откуда | замер |
|---|---|---|
| уровень пиров как **первичное** хранилище с интернированным целым | «ленивый» | стоит около нуля (167.2 Б с ним и без него) против +47 Б у дубликата со строковым ключом |
| своя таблица интернирования id вместо `Map` | «бинарный» | `get` 5.4 против 30.4 нс, вставка 14.8 против 62.8, 39.4 против 61.8 Б/узел |
| группировка `order` на `Int32Array` | «бинарный» | 65.0 → 21.8 мкс на тысяче детей, ценой +10 Б/юнит |
| `adopt` — чужой буфер пачки главой арены, без копии | «ленивый» | 2.87 мс против 3.9–4.7; прямой ответ на долг [S2](11-roadmap.md#замеры-s2-2026-08-15) |
| ленивый вид: заводится только на читанный узел | оба | жадный разбор стоит **+194 Б/юнит** — независимое воспроизведение долга S2 (192 Б) |

Поля торчат наружу **свойствами, а не методами**. Довод не эргономический, а
измеренный: тесты слоя ленда читают поля напрямую в **125 местах**; методы
`self()` ломают все, свойства — ни одного сверх трёх фабрик. Заодно это снимает
цену `Link.pawn` (147.9 нс, до 40 % локальной записи) с горячего пути — внутри
ленда объектная обёртка над идентификатором не нужна нигде, ключ читается прямо
из байт за 2.3 нс.

**Следствие для S4, важнее самого выбора.** Раз память определяется числом
подписок, а не представлением, слой моделей обязан их экономить — и
[05](05-model-api.md) это уже делает решением Р2: кэш поля живёт в описании поля
(`computed.keyed` по `head`), а не в сущности, поэтому поле, прочитанное у 10 000
документов, — это записи в двух картах, а не 10 000 файберов.

**Два вопроса, вскрытые замером, доопределены.** Оба к представлению не сводились:
прототипы разошлись в них молча, и молчаливое расхождение — худший вид, потому что
в таблице чисел оно не видно.

*`size()` — число юнитов, включая проигравших по LWW.* Три прототипа понимали его
по-разному (11 000 / 10 000 / 11 000 на одном входе). Выбрано «юниты», потому что
на этот счётчик обопрутся `diff` и `summ` из [08](08-sync-protocol.md): они считают
юниты **по пирам** для обнаружения потерь, и выброшенные проигравшие сломали бы
досылку. Живые узлы даёт отдельный `count()` — разные вопросы, разные имена.

*Равное значение — ленд сигналит безусловно, гасит файбер.* Когда чужой юнит
выиграл LWW, но принёс то же значение, один прототип молчал, два будили. Выбрано
«будить», причём не из вкуса: у ядра уже есть структурное сравнение, и `Fiber.put`
возвращает `prev !== next`, то есть распространение гасится само. Если ленд начнёт
решать равенство сам, оно окажется **в двух местах сразу** — а расхождение двух
реализаций равенства это ровно тот класс дефектов, ради которого заведён реестр.
Одно решение, одно место. Тем же приёмом пользуется [05](05-model-api.md) в
решении Р3: `slot` пересчитывается, возвращает ту же строку, и значение не
декодируется вовсе.

**Что вскрылось при реализации** (`packages/core/src/land/`, бюджеты — раздел
`land_s4` в `bench/budgets.json`).

*«Включая проигравших» значит проигравших ЧУЖИХ.* Слот индекса — тройка
`(head, peer, self)`, и своя предыдущая версия ложится в тот же слот. Хранить и её
значило бы держать всю историю правок вечно, а `summ` из [08](08-sync-protocol.md)
считает юниты по пирам, и для него важно ровно то, что в слоте лежит. Первый же
тест на `size()` был написан с ожиданием «3» и оказался неправ — это уточнение
контракта, а не поблажка реализации.

*Уровень пиров как первичное хранилище не даёт `order` дешёвого обхода детей.*
Перебор трёхуровневого индекса — это итератор на каждую карту второго уровня и
обращение к карте на ребёнка; группировка на `Int32Array`, ради которой всё
затевалось, в такой оправе своего выигрыша не показывает (у «ленивого» с тем же
индексом `order` стоил 192 мкс против 21.8 у «бинарного» с плоским списком, и
разрыв тогда списали на представление). Поэтому рядом с индексом ведётся плотный
список детей головы: узел числится под головой своего победителя, дедупликация
версий разных пиров не нужна. Цена — **+12 Б на юнит** сверх опорных 166; замер
боевого ленда: **181 Б**, `order` на тысяче детей — **21.0 мкс**.

**Чем опровергается.** Если после переезда на байты `read/warm` не уложится в
бюджет S4 с запасом, если стабильная личность юнита (нужна S8 для keyed-рендера)
обойдётся дороже интернирования в «ленивом» (167 → 349 Б), или если S6 покажет,
что подпись всё равно требует держать разобранный вид, — решение пересматривается.
Прототипы остаются в `scratchpad/land-lab` как исходный материал.

Первая проверка «чем опровергается» пройдена: `read/warm` — **9.8 нс** при бюджете
72, и не потому, что байты быстрее объектов, а потому, что `LocalId` убрал с пути
чтения перевод идентификатора в номер узла (у прототипов он стоил 15–20 нс на
каждое чтение).

## ADR-015 · Арбитраж LWW определён на байтах пира 🟢

**Контекст.** При равном `time` победителя выбирает `peer ↑` — детерминированный
арбитр. Пока слой ленда работает на обычных объектах, `Sand.peer` — строка, и
`compare` сравнивает её оператором `<`. Реализация бинарного юнита вскрыла, что
это **не один** порядок, а два разных.

base64url ставит цифры (52…61) после букв, а символы `-`/`_` (62/63) в ASCII
идут **до** цифр. Проверено на боевом `compare` из `land/lww.ts`: пиры `0xf4…` и
`0xf8…` дают текст `"9AAAAAAAAAA"` и `"-AAAAAAAAAA"` —

| форма `Sand.peer` | результат `compare` |
| --- | --- |
| текст ссылки (base64url) | `+1` (побеждает второй) |
| hex | `−1` (побеждает первый) |

Оба порядка детерминированы и оба сходятся — но к **разным** ответам. Реплика,
сравнивающая пиров в тексте, и реплика, сравнивающая их в байтах, разойдутся на
конкурентных правках, и ни один тест на сходимость этого не покажет: каждая пара
реплик сходится сама с собой.

**Решение.** Канонический порядок арбитража — **лексикографический по байтам**
идентификатора пира. `Unit.compare` сравнивает байты (двумя `u32` — замер:
сортировка 1000 юнитов 156.1 → 125.0 мкс). Строковая форма допустима в
`Sand.peer` только сохраняющая порядок относительно байт: hex — да, base64url —
нет. При переезде слоя ленда на бинарный юнит сравнение обязано идти через
`Unit.compare`, а не через `<` над текстом ссылки.

**Обоснование.** Байты — единственная форма, общая для диска, сокета и памяти;
текстовая форма существует для человека и URL. Ставить порядок сходимости в
зависимость от кодировки для человека — значит сделать корректность CRDT
свойством представления.

**Последствия.** `land/lww.ts` пока остаётся на строках (S3 не переехал на
бинарный слой), но обзавёлся тестом-сторожем на это расхождение. Инвариант
записан в [03 §2](03-binary-format.md#2-unit--юнит).

## ADR-014 · Текст ссылки: стандартный base64url, разделитель — точка 🟢

**Контекст.** Первая редакция [03 §1](03-binary-format.md) требовала base64url и
разделитель `_` одновременно. Но `_` — 63-й символ самого base64url, и разбор
становился принципиально неоднозначным: `_AAAAAAAAAA` читается и как «секция peer
опущена», и как «peer начинается с `_`». Фиксированные длины секций этого не спасают.
Противоречие нашёл независимый исполнитель, реализуя спецификацию с нуля.

**Решение.** Алфавит остаётся **стандартным** base64url (RFC 4648 §5), разделитель
секций — **точка**.

**Обоснование — характер отказа.** Развилку можно было закрыть и подменой 63-го
символа (так делает baza: там алфавит с `æ`). Но с подменённым алфавитом любой
стандартный декодер — `atob`, `Buffer.from(s, 'base64url')`, консоль браузера —
**молча** выдаёт не те байты. В формате, весь смысл которого в побайтовом
хэшировании, тихая порча хуже громкой поломки. Со сменой разделителя стандартные
инструменты продолжают работать посекционно.

`.` не входит в алфавит и остаётся unreserved по RFC 3986 — ссылка по-прежнему
кладётся в URL без экранирования.

**Последствия.** Golden-векторы пересобраны. Сделано до появления первых данных —
позже это была бы несовместимость формата, а не правка.

## ADR-013 · Dev-детектор последовательных ожиданий 🟡

**Контекст.** В файберной модели `a(); b();` — это **последовательные** ожидания:
`a()` бросит промис, до `b()` дело не дойдёт до следующего прогона. Чтобы
получить параллельность, нужен явный `race(a, b)`. В $mol это ловушка по
умолчанию, о которой знают только посвящённые.

**Решение.** В dev-сборке считаем, сколько раз файбер приостанавливался за серию
прогонов. Два и более приостановок подряд на разных `sync()` без `race()` —
предупреждение с указанием обеих точек:

```
[sync] Land.loading() ждал последовательно 2 раза: store.load(), secret.decrypt()
       → возможно, стоит обернуть в race()
```

🟡 — уточнить эвристику после первых реальных профилей: возможны легитимные
случаи, где вторая приостановка зависит от результата первой.
