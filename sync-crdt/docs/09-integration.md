# 09. Переработка vue-sync-engine

Пакет **переписывается** поверх ядра, а не оборачивается адаптерами
([ADR-001](00-decisions.md#adr-001--отдельное-ядро-vue-sync-engine-переписывается),
[правило 1](../PRINCIPLES.md#правило-1--это-rd-совместимость-не-ограничение)).
Обратная совместимость не цель: внешних пользователей нет, а legacy-путь
консервирует ровно те абстракции, от которых мы уходим.

---

## 1. Что удаляется

| Файл | Строк | Почему |
|---|---|---|
| [core/patches.ts](../../vue-sync-engine/lib/src/core/patches.ts) | 48 | CRDT не нуждается в патчах и инверсных патчах |
| [worker/mutationQueue.ts](../../vue-sync-engine/lib/src/worker/mutationQueue.ts) | 144 | локальная запись — это юнит; очередь = несинхронизированные юниты |
| [tab/mirror.ts](../../vue-sync-engine/lib/src/tab/mirror.ts) | 168 | вкладка держит настоящий `Land`, а не слепок |
| `Msg.EntityPatch` / `Msg.QueryPatch` в [protocol.ts](../../vue-sync-engine/lib/src/transport/protocol.ts) | ~30 | по проводу летят `Pack` |
| `entityRefCount` / `entityPins` / `gcTimer` в [queryGraph.ts](../../vue-sync-engine/lib/src/worker/queryGraph.ts) | ~120 | GC по достижимости в графе файберов |

Итого около **500 строк** и вместе с ними — целые классы багов: рассинхрон
Mirror↔Graph, потерянные откаты, зависшие пины сущностей.

## 2. Что остаётся

| Что | Почему остаётся |
|---|---|
| `defineQuery` / `defineInfiniteQuery` | «когда идти на сервер» ортогонально CRDT |
| `staleTime` / `gcTime` | политика обращения к серверу |
| Дедуп подписок по `hashKey` | по-прежнему нужен |
| `useQuery` / `useInfiniteQuery` | форма API сохраняется, реализация новая |
| Vite-плагин автодискавери | не зависит от ядра |
| DevTools-панель | расширяется, см. §5 |

`defineEntity` **удаляется**: его роль полностью занимает `model()` из
[05](05-model-api.md), который вдобавок даёт типизацию полей, а не только
извлечение `id`. Держать два способа описать сущность — ровно та ситуация, ради
которой существует [правило 1](../PRINCIPLES.md#правило-1--это-rd-совместимость-не-ограничение).

## 3. Ключевой ход: запрос как импортёр в ленд

Сейчас `normalize()` кладёт сущности в `Mirror`. Станет — в **серверный ленд**:
обычный `Land`, где сервер является королём, а клиент имеет `read`.

```ts
export const postsQuery = defineQuery({
  name: 'posts',
  key: (p: { page: number }) => ['posts', p.page],
  fetch: (p, ctx) => api.get(`/posts?page=${p.page}`, ctx),
  // было: normalize → { entities, result }
  // стало: import → пишет в ленд через модели
  import: (resp, ctx) => {
    for (const p of resp.items) {
      const post = ctx.land(SERVER_LAND).doc(Post, p.id)
      post.title(p.title)
      post.author().ensure(null).name(p.author.name)
    }
    return resp.items.map(p => p.id)
  },
})
```

Что это даёт:

1. **Один стор.** `useQuery(postsQuery)` и `useDoc(Post, id)` возвращают одни и те
   же объекты. Сегодня это два независимых кэша.
2. **Оптимистичные мутации бесплатны.** Локальная правка — обычный юнит в
   локальном ленде. Когда сервер пришлёт свою версию — LWW выберет победителя.
   Ни `optimistic`, ни `inversePatches`, ни `rollback` не нужны.
3. **Офлайн бесплатен.** Несинхронизированные юниты просто лежат в хранилище и
   уедут при реконнекте — тем же механизмом, что и всё остальное.
4. **Кэш переживает перезагрузку** без отдельного `QuerySnapshot`: ленд и так
   персистентный.

Мутация становится такой:

```ts
export const renamePost = defineMutation({
  name: 'renamePost',
  local: (input, ctx) => ctx.doc(Post, input.id).title(input.title),
  push: (input, ctx) => api.patch(`/posts/${input.id}`, { title: input.title }),
})
```

`local` — синхронно и мгновенно. `push` — когда получится; провал не откатывает
UI, а помечает юнит как неотправленный.

## 4. Порядок работ

Не миграция, а замена. Три шага, каждый со своим гейтом.

| Шаг | Что делаем | Гейт |
|---|---|---|
| **R1** | Удалить `mirror`, `patches`, `mutationQueue`, `Msg.*Patch`, entity-GC. Тесты, привязанные к этим модулям, удаляются вместе с ними | сборка проходит, оставшиеся тесты зелёные |
| **R2** | `TabRuntime` переписывается поверх `Node`/`Land` из ядра; `useQuery` возвращает данные из ленда; `useDoc`/`useField`/`useList`/`useText` появляются | старый набор тестов `useQuery`/`useInfiniteQuery` проходит на новой реализации |
| **R3** | `defineQuery.import` заменяет `normalize`; `defineMutation` переезжает на `local`/`push`; `defineEntity` удаляется | playground переписан, бенчи из [10](10-testing.md) в бюджете |

**Ценное правило для R2.** Прежде чем удалять старую реализацию, прогнать её
тестовый набор против новой. Совпало — старая удаляется; не совпало — расхождение
разбирается по существу, а не подгоняется. Это не совместимость, а способ не
потерять поведение, которое кто-то однажды продумал.

Тесты, привязанные к **устройству** старой реализации (`applyEntityPatches`,
`invertEntityPatch`, `entityPins`), удаляются без сожалений: они проверяют
механику, которой больше нет.

## 5. DevTools

Существующая панель ([devtools.ts](../../vue-sync-engine/lib/src/devtools.ts),
758 строк) расширяется узлами:

| Узел | Что показывает |
|---|---|
| **Lands** | открытые ленды, размер, права текущего пира, шифрование |
| **Units** | лента юнитов с фильтром по пиру/голове; hex-дамп |
| **Faces** | матрица «кто с кем синхронен», отставание в юнитах |
| **Peers** | подключения, RTT, объём трафика |
| **Fibers** | граф файберов: кто чего ждёт, причина последнего пересчёта |
| **Time travel** | проигрывание истории ленда до произвольной отметки |

**Time travel** заслуживает отдельного внимания: юниты иммутабельны и тотально
упорядочены, поэтому «состояние на момент T» — это не снапшот, а честная
переигровка `applyUnits(units.filter(u => u.time() <= T))` в изолированный ленд.
Стоит почти ничего поверх уже готового ядра и не существует ни в одном
конкурирующем инструменте.

**Fibers** — инспектор графа из [02 §11](02-runtime-design.md#11-план-работ-по-пакету),
шаг F6. Без него отлаживать Suspense мучительно.

## 6. Playground

[playground](../../vue-sync-engine/playground) переписывается на шаге R3, а не
дублируется. Что он обязан показывать:

- две вкладки редактируют один документ и видят правки друг друга без сервера;
- офлайн: выключил сеть, поредактировал, включил — сошлось;
- совместное редактирование текста без чередования символов;
- запрос к серверу и локальная правка живут в одном сторе;
- time travel по истории ленда.

Это одновременно демо и приёмочный тест: каждый пункт — сценарий в `e2e/`.
